# 教学模式（把「情圣」内化成自己的能力）设计

第二条需求：不只是让情圣替我给答案，而是**在用的过程中学会它怎么分析，慢慢变成自己的东西**。

本文是这一层的完整设计。它是 [`DESIGN_ADVISOR_SWITCH.md`](DESIGN_ADVISOR_SWITCH.md) 的姊妹篇：
顾问切换解决「用谁的方法论」，本文解决「拿到答案之后怎么长本事」。

---

## 1. 先说一个关键契合点

情圣原文（`skill/SKILL.md`「第二步：给建议 → 深度分析模式输出结构」）规定，当用户一次粘贴 ≥5 条消息时，
**必须**按固定结构输出：

```
1. 时间线摘要（2-3 句）：她干了什么、互动目的与节奏是否变化
2. 关键信号点名（最多 3-5 条）：可观察事实 / 事务性礼貌 / 真正个人化信号 / 无法判断之处
3. 阶段定位（一句话）：按 stages.md 标签
4. 话术建议（1-2 条可直接发的文字 + 每条一句话原理）
5. 追问（采集下一轮关键信息）
```

**这一套本身就是教学骨架**——它区分事实与推测、点名信号、给阶段、给可执行动作、收集反馈。
也就是说：把「代打」改成「教学」不需要发明新方法论，而是把上游已经设计好的分析结构
**从"一条聊天回复"改成"分层展示的卡片"**，并且抑制其中 app 端无法执行的部分（追问）。

这个决定的意义：教学模式的骨架是原作者设计的、经过验证的，不是我们拍脑袋发明的。

---

## 2. 为什么"看 AI 给的答案"学不会

| 学习机制 | 代打模式缺什么 | 对应要做的功能 |
|---|---|---|
| **提取练习**（先自己想，再看答案） | 直接给答案，大脑零提取 | 先猜后给 |
| **即时反馈**（知道哪一步错了） | 只给成品，不说推理 | 骨架化拆解 + 差异点 |
| **结果反馈**（建议到底有没有用） | 完全不知道后果 | 结果回填（言外独有优势，见第 8 节） |
| **间隔重复**（同一原则反复遇到） | 每次都是新对话，无沉淀 | 原则卡片库 + 复习调度 |
| **迁移**（换场景还能用） | 只解决眼前这一个情境 | 固定骨架 + 变式练习 |

代打模式和教学模式的差别不是"要不要给话术"，而是**给话术的时机和包装**。

## 3. 四维正交模型

改造后系统有四个互不干扰的维度，各有默认值、各有持久化策略：

| 维度 | 取值 | 回答什么 | 持久化 |
|---|---|---|---|
| **顾问** advisor | 军师 / 情圣 | 用谁的方法论 | 随联系人保存 |
| **身份** relationship | 暗恋/暧昧/恋人/朋友/家人/同事… | 对谁、什么分寸 | 随联系人保存 |
| **模式** mode | 代打 / 先猜后给 / 只拆解 / 批改 | 要答案还是要学习 | **全局默认 + 本次覆盖** |
| **上下文** context | 消息 / 长期背景 / 本次补充 / 条数 | 具体情境 | 已有 |

注意模式**不按联系人记**：教学是一种习惯，不是某个联系人的属性。
在同一个联系人身上一会儿代打一会儿教学，会让"一致率"这类指标失去意义。
（这一点与顾问、身份的存储策略刻意不同。）

---

## 4. 四种模式与输出契约

| 模式 | id | 他要做什么 | 模型返回 | 内化什么 |
|---|---|---|---|---|
| 代打 | `assist` | 点生成（现状） | `replies` + `reason` | 应急用，不学 |
| 先猜后给 | `predict` | **先写自己的判断和回法** | 对比卡 + 建议 | 校准直觉 ★核心 |
| 只拆解 | `read` | 点拆解 | 骨架 5 步，**不给话术** | 学会看懂 |
| 批改 | `grade` | 自己写完整回复 | 评分 + 改法 + 更优版本 | 输出能力 |

输出契约（在现有 JSON 上向后兼容扩展，**旧的 `replies`/`reason` 字段保持不变**，所以 P0 不需要为此预留）：

```json
{
  "read": {
    "facts": ["可观察到的事实，最多 3 条"],
    "guess": ["推测，标注为推测，最多 3 条"],
    "purpose": "事务互动 / 私人互动，一句话，含判断依据",
    "stage": "阶段3（关系升温）",
    "trend": "升温 / 持平 / 降温，一句话",
    "her_need": "她此刻更想被怎么回应",
    "my_goal": "我这次想达到什么（来自 direction）"
  },
  "compare": {
    "keep": ["你这条里对的地方 —— 必须具体，不许客套"],
    "fix": ["具体改法 1", "具体改法 2"],
    "verdict": "一句话结论"
  },
  "replies": ["建议发送的短消息 1", "…"],
  "drill": "一句可迁移的原则，来自资料原文概念",
  "watch": "下次可以观察的一个点（代替无法执行的追问）",
  "reason": "为什么这样回（沿用现有字段）"
}
```

字段与模式的对应关系：`read` 字段在 `read`/`predict`/`grade` 模式返回；`compare` 只在 `predict`/`grade` 返回；
`replies` 在 `read` 模式下**必须为空**（否则他会忍不住看答案，提取练习失效）。

解析层的兼容策略：`ReplyProtocol.parse` 目前只要求 `replies` 存在，额外字段天然被忽略，
所以扩展不需要改协议版本号；`read`/`compare` 用可选解析，缺失就当没有。

## 5. 固定推理骨架（内化的载体）

每次拆解都按**同一副骨架**输出，位置和顺序固定不变。目的：重复到他能自己在脑子里跑一遍。

```
① 事实 vs 推测   她实际做了什么（可观察）｜我猜的（明确标注推测）
② 互动目的       事务 or 私人：换成普通同学/办事同事，她还会这样说吗？
③ 阶段与趋势     阶段 1-7 标签 + 回复节奏在升温还是降温
④ 她要的 vs 我要的  她此刻想被怎么回应 ｜ 我这次想达成什么
⑤ 下一条         一条可发的话（或：这条先别回，因为…）
```

与上游结构的对应：

| 骨架 | 情圣原文对应 | 改动 |
|---|---|---|
| ① 事实 vs 推测 | 关键信号点名（区分可观察事实/事务性礼貌/个人化信号/无法判断） | 原样保留 |
| ② 互动目的 | 「先判互动目的，再判阶段」+「换成普通同学她还会这样说吗」 | 原样保留 |
| ③ 阶段与趋势 | 阶段定位（stages.md 七阶段）+ 时间线摘要 | 合并 |
| ④ 她要的 vs 我要的 | 无直接对应（原文的「追问」位） | 替换：app 是单轮请求，追问无法回答，改成"下次观察点" |
| ⑤ 下一条 | 话术建议（可直接复制发出） | 原样保留 |

**第 ⑤ 步是提取练习的钩子**：`read` 模式下第 ⑤ 步留空，界面显示「你先写一条，写完再对比」，
必须他自己填过之后，才解锁「看建议」按钮。

## 6. 先猜后给（`predict`）交互细节

```
点击生成
  └─ 抽屉展开：「你的判断？」（一句话，可跳过）
                「你会怎么回？」（自由文本，可跳过）
  └─ 提交 → 生成 → 对比卡展开：
       ┌─────────────────────────────────┐
       │ 你的回法：一起吃个饭？            │
       │ 建议：周三那家店还开着吗，我去过两次 │
       │                                  │
       │ 你这条对的地方：直接、不绕、给了下一步 │
       │ 改法 1：没有具体的"钩子"，她只能回是/否 │
       │ 改法 2：借"那家店"把话题从日程挪到共同经历 │
       │                                  │
       │ ▸ 为什么（骨架 5 步）              │
       └─────────────────────────────────┘
```

设计要点：

- **可跳过，但要多点一下**：跳过要再点一次「直接看建议」，不让"零摩擦"成为默认；
- **先肯定再改**：`keep` 字段强制模型找出他版本里对的地方，且必须具体——目的是保住他的语言风格，
  避免他学成"AI 腔"。这条要写进提示词硬规则，并在测试里断言 `keep` 非空；
- **差异点最多 2 条**：一次给 7 条改法等于没给；
- **不展示"AI 版本更高级"的价值判断**，只展示"为什么会不同"。

---

## 7. 批改模式（`grade`）

他自己写完整的一段回复，模型只批改：

```json
{"score": 7, "keep": ["..."], "fix": ["..."], "replies": ["一条更接近他本人风格的版本"]}
```

硬规则：

- 输出的"更优版本"必须**延续他的用词和口吻**（提示词明确要求：不要用书面语替换他的口语）；
- `score` 只在他要求时展示（默认折叠），避免打分带来的挫败感压过学习动机；
- 这是"毕业模式"：用得越多，说明他越不需要代打。

## 8. 结果回填：言外独有的优势

情圣在 Claude Code 里永远不知道建议发出去之后发生了什么。**言外读得到聊天库**
（`ReplyHistoryReader` 已按 talker 参数查询双方消息），所以可以闭环：

| 指标 | 怎么取 | 成本 |
|---|---|---|
| 她是否回复 | 建议时间戳之后，该 talker 里她的下一条消息 | 0 |
| 回复间隔 | 与她历史回复间隔的中位数比较（快了/持平/慢了） | 0 |
| 是否她主动开新话题 | 她那条是否引出了新话题（启发式；可选模型判定） | 0 / 低 |
| 他是否采用了建议 | 建议 vs 他在建议之后发出的那条（相似度/编辑距离） | 0 |
| 情绪走向（可选） | 建议前后各 5 条做一次轻量情绪对比（复用现有分析线路） | 1 次调用，默认关 |

**回填时机**：不做后台服务、不加常驻任务。下次打开该联系人的抽屉时顺带回填上次记录
（那时新消息已经在本机库里了）。这样零额外基础设施，也不违背"不自动上传聊天"的产品约定。

有了这一列数据，第 10 节的错题本才有意义——否则只是"AI 说过什么"的流水账。

## 9. 记录与存储

复用言外自己的 SQLite（`AnalysisCacheDatabase`），新增两张表；沿用现有 5000 条 / 32 MiB 上限与 LRU 清理策略。

```sql
CREATE TABLE IF NOT EXISTS learn_records (
  record_id    TEXT PRIMARY KEY NOT NULL,
  contact_key  TEXT NOT NULL,
  created_at   INTEGER NOT NULL,
  mode         TEXT NOT NULL,   -- assist | predict | read | grade
  advisor      TEXT NOT NULL,   -- junshi | qingsheng
  relationship TEXT NOT NULL,
  her_text     TEXT NOT NULL,   -- 触发消息，截断保存
  my_draft     TEXT,            -- 他的猜/他的回法
  coach_read   TEXT,            -- 骨架化拆解（JSON）
  suggestion   TEXT,            -- 建议（JSON 数组）
  picked       TEXT,            -- 他实际复制的那条
  outcome      TEXT,            -- 回填结果（JSON）
  drill_id     TEXT             -- 关联卡片
);
CREATE INDEX IF NOT EXISTS learn_records_contact ON learn_records(contact_key, created_at);

CREATE TABLE IF NOT EXISTS learn_cards (
  card_id    TEXT PRIMARY KEY NOT NULL,
  principle  TEXT NOT NULL,   -- 一句可迁移的原则
  evidence   TEXT NOT NULL,   -- 它首次出现的真实片段（记忆锚点）
  source     TEXT NOT NULL,   -- 来自哪个顾问/哪份资料
  hits       INTEGER NOT NULL,-- 又遇到过几次（说明它反复适用）
  box        INTEGER NOT NULL,-- Leitner 盒子 1..4
  due_at     INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

隐私约定（沿用现有边界，不新开口子）：

- 记录只进言外自己的私有目录，**不写入微信数据库、不新增公共存储文件**；
- 统计与卡片库**不带聊天原文**，只有他自己点开某条记录才看到原文；
- 导出 Markdown 时，正文默认脱敏（可手动选择包含原文）；
- 卸载言外或清数据即删除（与现有缓存行为一致）。

## 10. 卡片库与间隔重复

- 每次生成附带 `drill`：一句可迁移的原则，来自情圣原文的概念体系
  （浅话题 pivot 到感受、事务性礼貌 ≠ 好感信号、冷读要准不要油、主动 vs 被动、节奏与间隔…）。
- **首次出现入库，之后每次遇到同一原则 `hits + 1`**——反复适用的原则自动浮到前面，
  这是天然的"哪些知识对我真有用"排序，不需要他手动打分。
- 复习调度：简化 Leitner 四盒（1 天 / 3 天 / 7 天 / 21 天），"记住了"进下一盒，"还不熟"退回第一盒。
- 每张卡必须**带真实场景**（他经历过的那个片段），而不是抽象定义——记忆锚点在情境里。

## 11. 怎么量化"内化"（能力曲线）

| 指标 | 含义 | 计算 |
|---|---|---|
| 一致率 | 他的猜与建议的接近程度 | 启发式（长度/关键词/意图标签）先做；可选模型判定 |
| 采纳率 | 他多大比例直接采用建议 | 复制行为 + 发送内容相似度 |
| 结果差异 | 采用建议 vs 他自己回，回复率/升温率的差别 | 第 8 节指标聚合 |
| 阶段曲线 | 同一联系人 30 天内在阶段 1-7 上的移动 | 每次 `read.stage` 落库后画线 |
| 卡片掌握度 | 四盒分布 | 卡片表 |

这页是整个产品的"毕业感"来源，也是他能坚持下去的反馈机制。**默认只在 APP 内可见，
不塞进微信聊天界面**——微信里只留学习动作，不留统计。

## 12. UI 落点

**微信抽屉**（空间紧张，只加最小控件）：

- 「本次补充」同一行右侧加一个紧凑胶囊 `[模式 ▾ 代打]`，四个选项；
- `predict` / `grade` 时在输入框下方展开「你会怎么回？」（`predict` 为可选，`grade` 为必填）；
- 结果卡：拆解区（骨架 5 步，默认折叠）→ 对比区（`predict`/`grade`）→ 建议 → `drill` 一行小字；
- 「这条先别回」也是一个合法结论，界面上要与"给话术"同等醒目，不能显得像失败。

**言外 APP「学习」页**（底部新增第 5 个入口）：

- 今日 3 张卡（间隔重复）；
- 错题本时间线：按联系人分组，展示"我的判断 / 模型判断 / 后来发生了什么"；
- 能力曲线：一致率、采纳率、结果差异、阶段曲线；
- 导出 Markdown（可存到 Obsidian 一类本地库）。

| 项 | 增量 |

## 14. 分期

| 期 | 内容 | 判断标准 |
|---|---|---|
| **P2** | 三种教学模式（`read`/`predict`/`grade`）+ 骨架化拆解 + `drill` 卡片 | 同一次请求内完成，能开始练 |
| **P3** | 记录落库 + 结果回填 + 错题本 + 间隔重复 + APP「学习」页 | 有闭环反馈 |
| **P4** | 能力曲线、导出 Markdown、可选情绪对比、变式练习（同原则换场景） | 可量化进步 |

P2 与顾问切换的 P0/P1 是**并行可做**的：它们共享同一个 JSON 契约扩展点，但互不阻塞。

### 14.1 P2 的实现取舍（已落地）

| 设计里写的 | 实际做法 | 原因 |
|---|---|---|
| 模式「全局默认 + 本次覆盖」 | **只做本次覆盖**，默认代打，进程内保留 | 全局默认要新增一条跨进程同步的设置链路；先把功能做出来，设置项留到 P1 |
| `predict` 跳过要多点一下 | 先猜后给允许留空草稿 | 同上，`compare` 只在**带了草稿**时才强制要求，没草稿时退化成「只拆解 + 建议」 |
| `drill` 卡片入库 | 本阶段只在结果里显示 | 入库要走 app 进程的 provider，和复盘层（错题本、复习调度）一起做才有意义 |
| 空 `replies` 只在只拆解 | 解析层按模式分别校验：只拆解必须为空数组，其余模式仍是 1–6 条 | 原有「空数组即失败」的严格性只对旧模式保留 |
| 评分默认折叠 | `score` 可选（0–10），超出范围当作没有 | 服务商不给就不显示，不猜

## 15. 风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| 教学输出变长 | 响应慢、token 贵 | 拆解默认折叠；长度上限随模式区分 |
| 他永远只用代打 | 教学层形同虚设 | 温和的一次性引导（可永久关闭），不弹窗骚扰 |
| 直接指出"你这句掉分" | 挫败，弃用 | `keep` 强制非空且具体；评分默认折叠 |
| 模型把他的话改成 AI 腔 | 学歪，越学越假 | 提示词硬规则：延续他的用词；测试断言"更优版本保留他的关键词" |
| 记录含聊天原文 | 隐私 | 本地私有目录、统计脱敏、导出可选、随卸载删除 |
| 一致率等指标太粗糙 | 曲线无意义 | 先用可解释的启发式，宁可指标少也不要假精确 |
| 骨架固定导致模板化 | 输出千篇一律 | 骨架固定的是**结构**不是措辞；drill 与 watch 每轮必须不同 |

## 16. 待拍板

1. **教学模式的默认值**：默认代打（想学时手动切），还是默认先猜后给（学习优先）？
